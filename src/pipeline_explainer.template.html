05程式碼是怎麼被呼叫的

兩條管線都是「一個指令讀上一步的檔案、寫下一步的檔案」。先看呼叫順序，再看三個最關鍵的想法。

想法 ①　畫面＝f(時間)

每一幀都是「第 t 秒該長什麼樣」算出來的，不是錄下來的。拖動看看。

t = 1.80 秒　畫面指紋 —

為什麼這樣設計？

  • 可重現：同一個 t，永遠畫出同一張圖（右邊指紋一樣）。
  • 可局部重跑：只改第 3 場，就只重畫第 3 場。
  • 可亂序：隨便跳到哪一幀都行，所以能平行抽幀檢查。
// 本專案動畫場景的形狀（節錄自 scenes-a.js）
SCN['s00-title'] = (c, K) => {
  const t = K.t;   // 場景內第幾秒
  // …用 c（Canvas 畫筆）依 t 畫出這一幀…
};
// 全片由 renderFrame(frame) 決定畫什麼

類比：像翻頁動畫書——每一頁獨立畫好。類比不成立之處：這裡的「頁」是用數學式算的。

想法 ②　旁白多長，場景就多長（時間軸從音檔推導）

拖動「旁白字數」。這是依 film.json 的估算語速（每秒 4 字）算的示意；實際以 TTS 音檔長度為準（本機實測 Kore 約 4.47 字／秒）。

旁白 90 字 ➜ 念 22.5 秒　＋ 前導 0.25 ＋ 尾巴 0.45 ＝ 場景 23.2 秒 ＝ 695 幀（30 fps）

灰＝前導與尾巴的停頓、青＝旁白。字多就變長，場景會自動跟著拉長，不靠硬塞或拉慢播放。

想法 ③　cue：讓音效剛好落在關鍵字上

程式用「這個片段在整句的第幾個字」估算它被念出來的時間。點一個片段，看音效會放在哪（示意，假設這句旁白念 6 秒）。

# 實際用法（節錄自 make_audio.py）：fragment 必須和旁白逐字一致
ev(cue(S, '二十九點六倍', 0, -.2), sfx_ding(988, 1.0), .9)
#   cue(場景, 片段, 第幾次出現, 偏移秒) → 時間點　→ 在那個時間放「叮」

因為是依字數估算，會有零點幾秒誤差，所以才有偏移參數，也有 cue_check.py 檢查片段有沒有對上。字幕與音效對時是估算，不是逐字對齊。

07產出與上線

檔案怎麼放、哪些進 Git、哪些網址能看。

為什麼 main 不放影片？
film.mp4 約 74 MB、story.mp4 約 17 MB，放進 Git 歷史會讓倉庫變胖；影片只放 gh-pages 與 Vercel，.gitignore 擋掉。
為什麼兩支影片都能拖進度條？
伺服器要支援 Range 請求（回 206），影片也做了 faststart（索引放檔頭）。Vercel 兩者都有。

10踩過的坑與誠實的限制

做的過程中真的遇到、並修掉的問題；以及目前還沒做到的事。

簡體字配圖不能用介紹文章的圖是簡體版 → 全部改從真實報告重新擷取繁體畫面。
TTS 音檔速度被加快 1.84 倍TTS 是 24 kHz，混音時間軸是 44.1 kHz；直接貼會變快 → 先重新取樣。
手填章節秒數會錯章節秒數一律由 timeline.json 的場景起點產生。
影片只複製一半（moov atom not found）ffmpeg 還沒結束就複製 → 等它跑完再複製。
GitHub Pages 載入影片很慢是這台機器連 Pages 被限速（約 55 KB/s），不是檔案問題；Vercel 約 8.5 MB/s → 對外用 Vercel。
本機測試拖不動進度條Python 內建 http.server 不支援 Range → 改用支援 Range 的伺服器測。
頁面橫向捲動溢出grid 子元素加 min-width:0。
數字別說過頭預算執行率 110.5% 是「超支」不是達標；授信是備用額度不是現金；遠期後淨敞口反而 +207.8。
限制：旁白沒有人工聆聽發音與數字讀法請自行確認；兩支影片都一樣。
限制：沒有獨立評審只做自查（抽幀、量測、數字對 DAX）。
限制：字幕與音效是估時依字數比例估算，非逐字對齊，可能差零點幾秒。
限制：資料是示範（模擬）資料不代表任何真實公司；動畫畫面為示意，不是報告截圖。
